## Makefile
Automatic variable
- $@ target name
- $? all prerequisites newer than target
- $ ^ output all prerequisites
- $< output the first prerequisite

Implicit rules
- Compile a C program `$(CC) -c $(CPPFLAGS) $(CFLAGS) $^ -o $@`
- Compile a C++ program `$(CXX) -c $(CPPFLAGS) $(CXXFLAGS) $^ -o $@`
- Linking a single object file `$(CC) $(LDFLAGS) $^ $(LOADLIBES) $(LDLIBS) -o $@`

Implicit vars
- `CC` Program to compile C progs default cc
- `CXX` Program to compile C++ progs default g++
- `CFLAGS` Extra flags to give to the C compiler
- `CXXFLAGS` Extra flags to give to the C++ compiler
- `CPPFLAGS` Extra flags to give to the C preprocessor
- `LDFLAGS` Extra flags to give to compilers supposed to invoke the linker

## Libft Problems

### Void pointer dereference / memset
**Question:** Casting `void *` to `unsigned char *`, then dereferencing to implement `memset`, gives `error: dereferencing 'void *' pointer` and `invalid use of void expression` even with `-Werror`.

**Answer:** `ptr[i]` is `*(ptr + i)`. Pointer arithmetic needs a complete type — `void` is incomplete, so `ptr + i` is ill-formed (GCC's `void *` arithmetic is a non-standard extension, rejected under `-Werror`/`-pedantic`). Even if allowed, `*(ptr + i)` yields a `void` expression, which is not a modifiable lvalue — hence "invalid use of void expression". The cast doesn't help if the *result* is stored back into a `void *` variable: a variable's type is fixed at declaration; the assignment implicitly converts the cast result right back to `void *`. Fix by indexing through a variable (or inline expression) whose declared type is `unsigned char *`.

### Modifying original memory without returning (bzero)
**Question:** Implementing `bzero` (returns `void`) without return — does editing through a local `unsigned char *` actually change the original memory block?

**Answer:** Yes. A `void *` parameter carries the original block's address; `unsigned char *p = (unsigned char *)ptr;` copies that address, so `p` and `ptr` point to the same memory. `p[i] = 0;` writes through that address into the block itself — independent of which pointer variable is used. `bzero`'s effect is a side effect (mutating memory), not a return value, so no return is needed. Only fails if you make `p` point elsewhere or never write through it.

### strchr
**Question:** This `ft_strchr` "apparently cannot be done this way":

```c
char *ft_strchr(const char *s, int c)
{
    int i = 0;
    while (s[i])
    {
        if (c == s[i])
            return (s + i);
        ++i;
    }
    if (c == s[i])
        return (s + i);
    return (NULL);
}
```
